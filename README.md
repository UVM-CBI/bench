# CBI Bench

Short projects from the Center for Biomedical Innovation at UVM. Claim one,
build it, gain experience.

May range from less than four hours to a week, a month, or sometimes longer. Different tracks, including engineering, business, and media.

**New here?** → **[Start with ONBOARDING.md](ONBOARDING.md)** — takes about fifteen minutes,
assumes no GitHub experience.

## Who can do these

Any UVM student. You don't need to be in CBI.
You just need the skill the task asks for and the time it asks for. Each issue says what it
actually requires.

### What the labels mean

| Label | The work |
|---|---|
| `cad` | Mechanical design, solid modeling, fixtures and housings |
| `firmware` | Embedded code, microcontrollers, sensor drivers |
| `pcb` | Schematic capture and board layout |
| `software` | Scripts, data pipelines, small apps, test tooling |
| `analysis` | FEA, simulation, statistics, data analysis |
| `fab` | Machining, 3D printing, assembly, benchtop builds |
| `market-research` | Competitive landscape, customer discovery, market sizing |
| `regulatory` | FDA pathways, predicate searches, standards, reimbursement |
| `ip-search` | Prior art and patent landscape searches |
| `finance` | Cost models, build-vs-buy, budget analysis |
| `design` | Figures, posters, diagrams, slides, branding |
| `video` | Demo videos, process documentation, editing |
| `web` | Site updates, landing pages, small front-end work |
| `writing` | Technical documentation, protocols, articles, case studies |

## Claiming

Claims happen in Teams, not here. Post in `#open-tasks` in the **CBI Bench** team
with how you'd approach it and when you'd finish. Full version:
[CLAIMING.md](CLAIMING.md).

**Join CBI Bench:** [CBI Bench Team](https://teams.microsoft.com/l/team/19%3AtD7F5aKaYMGC-Vrk-voFuQmIonEXmqkrh6DxcwBdjOE1%40thread.tacv2/conversations?groupId=4ceb6b44-4d17-40a4-990e-b2c6202a35b4&tenantId=1c177758-4d6b-43dc-aaeb-3b9c42562967)

**Then post your GitHub username in `#general`.** You need to be in the UVM-CBI
GitHub org before you can be assigned a task, and that takes a day or two. Do it
when you join, not when you find something you want.

Don't have a GitHub account? <https://github.com/signup> — free, three minutes,
and it's the only part of GitHub you have to learn. Walkthrough in
[ONBOARDING.md](ONBOARDING.md).

## Why bother

- Real work with a real deliverable.
- Your contributions are public and are things you can point to in future interviews.
- You get a low-stakes opportunity to hone existing skills or build new ones.
- Some of these grow into paid positions, capstones, or longer
  projects.
